# Технічні рішення та допущення

Документ фіксує рішення, прийняті агентом самостійно там, де ТЗ не давало
однозначної відповіді. Власник проєкту (@427460325 в Telegram) може
скасувати будь-яке з них у будь-який момент — просто напишіть новий пункт
нижче або поправте код, і наступний запуск агента підхопить зміну.

## Стек

- **Python 3.12**, монорепо, один venv.
- Боти: **aiogram 3.x** (async, найпопулярніша бібліотека для Telegram-ботів на Python).
- Веб (Admin Panel + Partner Cabinet): **FastAPI + Jinja2** (server-rendered HTML,
  без окремого JS-фронтенду й build-кроку — менше рухомих частин для MVP).
- БД: **SQLite** через SQLAlchemy на старті (нуль конфігурації, один файл).
  Модель даних одразу через SQLAlchemy ORM, тож перехід на Postgres пізніше —
  це заміна `DATABASE_URL`, без переписування коду.
- Тести: `pytest`.

## Відкриті питання ТЗ — робочі допущення

1. **Модерація Community Bot** — у v1 бот лише інформує (розсилка новин/акцій/
   результатів розіграшів + FAQ). Функції модерації груп — заглушка/не
   реалізується, поки замовник явно не попросить.
2. **Публікація результатів розіграшу** — Community Bot надсилає результати
   в Telegram-канал/групу, у які його додано (список чатів — налаштування в
   Admin Panel), і дублює в межах свого функціоналу (FAQ/команда "результати").
   Окрема веб-сторінка — поза v1.
3. **Мотивація продавців для першої акції** — реалізуються всі 4 механіки
   (фіксована, градація, призи за рейтингом, комбінована) як налаштування
   кампанії в Admin Panel; яка саме активна — обирає DSM при створенні акції.
   Технічно всі мають бути готові, а не тільки одна.
4. **Метрика приросту партнерської мережі** — сума закупівель у грн
   (period-over-period), найпростіша й найочевидніша інтерпретація. Кількість
   продукції зберігається окремо в статистиці й може бути додана як друга
   метрика без зміни моделі даних.

## Звітність власнику в Telegram

Після кожної робочої сесії (кожен запуск за розкладом) агент надсилає власнику
(chat_id `427460325`) через бот-токен з `.env`:
- короткий текстовий звіт: що зроблено, що далі, чи є що узгодити;
- 1–3 скріншоти ключових екранів Admin Panel / Partner Cabinet, якщо в цій
  сесії з'явився новий UI (`playwright` headless chromium рендерить локально
  запущений FastAPI, зберігає PNG, скрипт відправляє через Bot API
  `sendPhoto`).

Реалізація: `scripts/report_telegram.py` (текст + фото) і
`scripts/screenshot.py` (рендер сторінок у PNG). Викликаються в кінці кожного
циклу розкладу — див. `PROGRESS.md` і промпт cron-агента.
