# Дорожня карта

Кожен пункт має конкретний критерій "готово" — саме він є стоп-умовою для
цього кроку, а не абстрактне "ідеально". Виконувати послідовно; якщо
залежність не готова — не пропускати вперед.

- [ ] **M0 — Каркас проєкту**
  DoD: `pyproject.toml`/`requirements.txt`, структура папок
  (`bots/promo_bot`, `bots/community_bot`, `webapp/`, `shared/models.py`,
  `scripts/`, `tests/`), SQLAlchemy engine + Alembic-подібна ініціалізація
  БД (можна без Alembic — `Base.metadata.create_all` для MVP), `pytest`
  запускається (нехай на порожньому наборі тестів), README з інструкцією
  локального запуску.

- [ ] **M1 — Модель даних**
  Таблиці: продуктові лінійки, партнерські мережі, продавці, покупці, акції
  (campaign, з прив'язкою до 1/декілька/усіх ліній), продажі (sale),
  шанси розіграшу (raffle_entry), призи (prize), розіграші (raffle,
  raffle_result). DoD: міграція створює всі таблиці, є тест, що перевіряє
  створення запису кожного типу і базові зв'язки (FK).

- [ ] **M2 — DSM Promo Bot: реєстрація продажу**
  Продавець (вже активований партнером) реєструє продаж: телефон покупця,
  лінійка (з активної акції), кількість, опційно ім'я. DoD: happy-path
  тест на handler (не потрібен живий Telegram — aiogram тестується без
  мережі через прямі виклики handler-функцій), запис зберігається в БД,
  генеруються шанси на розіграш згідно правил акції.

- [ ] **M3 — DSM Promo Bot: статистика й рейтинг продавця**
  DoD: продавець бачить кількість продажів, кількість проданої продукції,
  місце в мережі, місце по акції. Тест на розрахунок рейтингу з фікстурою
  з кількох продавців.

- [ ] **M4 — Partner Cabinet (веб)**
  Логін представника мережі, запросити/активувати/деактивувати продавця,
  перегляд статистики й рейтингу своєї мережі. DoD: інтеграційний тест
  через FastAPI `TestClient` на кожну дію, партнер не бачить чужі мережі
  (перевірка ізоляції даних — це trust-boundary, не спрощувати).

- [ ] **M5 — Admin Panel: продуктові лінійки й акції**
  CRUD ліній, створення акції з вибором ліній (1/декілька/усі) та правил
  нарахування шансів. DoD: тести на CRUD, акція без активних ліній
  неможлива (валідація).

- [ ] **M6 — Механіки мотивації продавців**
  Налаштування в акції: фіксована / градація / призи за рейтингом /
  комбінована. DoD: для кожної механіки — тест, що на заданому наборі
  продажів рахує правильну винагороду.

- [ ] **M7 — Призи й розіграш**
  Admin Panel: CRUD призів, запуск розіграшу після завершення акції.
  DoD: тест, що розіграш формує список учасників за шансами, обирає
  переможців детерміновано за фіксованим seed (для відтворюваності тесту),
  зберігає результат.

- [ ] **M8 — DSM Community Bot**
  Розсилка новин/акцій, публікація результатів розіграшу в налаштований
  чат/канал, базовий FAQ. DoD: тест на формування тексту розсилки й на
  виклик send до потрібного chat_id (мокований bot client).

- [ ] **M9 — Контроль підозрілої активності**
  Поріг (за замовчуванням 20 продажів/добу, налаштовується) →
  сповіщення DSM і партнеру. DoD: тест, що перевищення порогу генерує
  сповіщення, а значення нижче порогу — ні.

- [ ] **M10 — Звіти**
  Admin Panel: статистика продажів/ліній/акцій, рейтинг продавців/мереж,
  результати розіграшів. DoD: кожен звіт покритий тестом на коректність
  агрегації на фікстурних даних.

- [ ] **M11 — Приріст партнерської мережі**
  Порівняння закупівель період-до-періоду. DoD: тест на розрахунок приросту
  на двох періодах.

Кожен пункт = окремий(і) коміт(и) із зеленими тестами на момент коміту.
Прогрес між сесіями відстежується в `PROGRESS.md`.
